# 0.3.2 玻璃与交互实现说明

## 玻璃管线

播放控件使用完整视频 Surface 坐标映射，保留缩放、裁剪及屏幕原点。PixelCopy 单次在途，后台复制、主线程发布；最多2560×1440像素。30/60/90/随屏设置是采样上限，不意味着把30fps片源复制成120fps。默认60。

连续模糊0–100默认0；0跳过模糊，其他档使用系统GPU Gaussian RenderEffect，最大24dp、三倍半径边界扩展，边缘反光及前景不参与背景模糊。传输和锐利边缘分别使用独立RuntimeShader，避免修改已记录图层的通道参数。

透明控件不再使用平台elevation阴影：透明显现期间，实体投影的内部三角剖分轮廓可能透出。保留光学边缘反射。移除了将整个控件子树重复绘成黑色阴影的实现，避免连点击反馈、子图层一并复制；Material点击反馈仍保留。

跳转使用请求代次与渲染器提交证据，过期复制结果被拒绝；真正未触发内部reset的跳转经播放线程FIFO完成确认后才恢复原代次。FFmpeg等待本次enable真实计数器到达，使用同一render调用前后差值，不以累计猜测代替输出。暂停时未知帧在短暂显现期后降低轮询频率。

**边界：**输出提交、截止时间和有限重采样不等于合成器逐帧PTS证明。真机录屏也不保证捕获每个显示周期；不得据最终截图断言绝无单帧旧图。

## 弹窗遮挡和遮罩

弹窗不再直接复用纯视频背景。其背景捕获下层Window UI，在SurfaceView透明区域合成视频，再应用当前弹窗的实际dimAmount。当前弹窗不包含在采样源内，完整合成背景不再重复应用视频专用的对比度提升和着色。单次在途、最高约15Hz，只在可见生命周期工作，待帧时保持透明。

K20 Pro/API35实测：属性窗口能透出后方播放按钮、进度条与底部图标；均匀绿色区域，修复前内侧绿通道中值252、外侧100，修复后内外100。证据见[明暗对比](testing-v032/dialog-dim-comparison.json)及[横屏截图](testing-v032/k20-r18-dialog/dialog-backdrop/screenshots/dialog.png)。其他设备的Window透明区域行为需要单独验证；不得用黑色像素猜测遮挡区域。

## 手势与预览

长按倍率默认2×，可设1.25–3×，松手恢复先前速度；常规速度包含3×。倍率和双击播放/暂停提示位于顶部安全区域，避开字幕。进度和真实帧预览仍留底部。时间栏保留固定宽度，避免更新时拖动滑轨。

预览500ms分桶，时间接受范围目标前100ms至后500ms；单次在途并保留最新请求。冷启动8s、热5s、HTTP3s，有限重试与恢复。单请求12MiB、单手势32MiB，缓存32MiB，离开/STOP释放，启动前有界清理本应用遗留缓存。实际限制和失败均保留诊断，不能把目标时间直接当实际帧时间。

## 本设备证据与待验收项

新测试设备为Redmi K20 Pro、Android15/API35。原生/GPU/FFmpeg暂停红绿蓝跳转及快速连续跳转通过；暂停旋转与桌面返回通过。30fps片源10秒301帧、零丢帧，玻璃约30次/秒。

移除系统投影后的录制已保留在[无投影对照](testing-v032/k20-r19-no-elevation/transition/transition.mp4)。采样接触图未见用户截图的明显多边形；仍需覆盖加载瞬间、不同模糊档和底部大栏，不能仅凭采样图宣布全部消失。
